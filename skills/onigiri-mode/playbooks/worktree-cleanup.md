### Worktree and disk cleanup

1. Snapshot and audit. Record `df -h /`, then run `../scripts/worktree-audit.sh [-b <base-ref>] [repo-path]`. Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that a tool put somewhere else entirely (the **principle-encode-lessons-in-structure** skill). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest pi session that touched it, then suggests a bucket. The session scan is slow, so background it.
2. The bucket is advice, not permission. Pinned and active sessions are the real artifact (the **principle-prove-it-works** skill). Get that set from the user, and cross-check every candidate against it. The script has marked `safe` a worktree the user still had pinned, so their word wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, read the session and establish whether that work is pinned or ongoing and which worktrees it touches (the **principle-guard-the-context-window** skill; sessions are bulk). A worktree in active use is in use even when its name never came up in conversation.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Clean, merged, and not-in-use proceeds without asking. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Other reclaimers on the VM. Package caches are usually the next-biggest win: `pnpm store prune`, `npm cache clean --force`, `uv cache clean`, `bun pm cache rm`. Then old pi sessions under `~/.pi/agent/sessions/` for directories that no longer exist, and build output under a worktree you kept. Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which session, or uncommitted work).
