# rule-guard extension

`extensions/rule-guard/` turns the outright bans in onigiri-mode's Hard rules into code: a `tool_call` handler blocks the call and returns the reason, so the model sees a refusal it can act on. The matcher is `rules.ts`, a pure module, and `tests/rule-guard.test.ts` is the list of what is and is not blocked, case by case.

## What it blocks

1. **Force-push and skipping the pre-push hook.** `git push` with a force flag or a `+refspec`, `--no-verify`, and a `core.hooksPath` override on a push. The patent hold lives in the pre-push hook, so a hook skip is a patent-hold bypass.
2. **Merging or readying where a merge job owns merging.** `gh pr merge`, `gh pr ready`, and the `gh api` and GraphQL calls that do the same, in `trycua/cua` (`MERGE_OWNED` in `rules.ts`). CI reruns (`gh run rerun`, with or without `--failed`, and the actions rerun API calls) are not blocked: Zane (11 Nov) has sessions decide reruns without asking him, and only real failures go to him. The guard can't tell a runner network failure from a failure the diff caused, so the session makes that call. Approving a fork's workflow runs (`gh api -X POST repos/trycua/cua/actions/runs/<id>/approve`) is not blocked either: Zane (12 Nov 11:45 SGT) lets sessions approve outside-contributor runs on trycua/cua so CI runs. Review still comes before any merge, and the merge job still merges. The repo comes from `-R`, a URL, the `gh api` path, `GH_REPO`, or the `origin` remote of every directory the command might run in. A repo that can't be told is blocked, so name it with `-R` to merge elsewhere from an owned checkout. When the brief has a line exactly `merge: allowed`, `bin/pi-run` sets `ONIGIRI_READY_ALLOWED=1` and `gh pr ready` runs; merges stay blocked. The guard reads the flag once at load and removes it from the environment, and refuses a bash command that names it other than as a bare `$ONIGIRI_READY_ALLOWED` read. Edit files that mention it with the `edit` tool.
3. **Writing the real holds file.** A `write` or `edit` of it, and bash that redirects into it, edits it in place, removes or moves it, or copies over it. Reads, diffs and copies out still run. The real holds files are `$ONIGIRI_ROOT/hold-prs.txt` (default `~/onigiri`), `/srv/onigiri/hold-prs.txt` and the mini's copy `~/onigiri/sync/hold-prs.txt` (`holds.ts`), read once at load. A path is matched after resolving it against the command's directory and following symlinks, so a link to the file or to its directory counts, as does a hard link. A `hold-prs.txt` anywhere else, in a test root or a throwaway HOME, is an ordinary file (Zane, 11 Nov). A path the guard can't resolve counts when its name is `hold-prs.txt`, in any case on macOS. That covers a variable, glob, brace or substitution, any path on a remote host, a path it can't walk (a symlink loop), and a relative path after a directory change it can't follow: a relative `cd` (which `$CDPATH` may redirect), `cd ~`, `cd -`, `pushd`/`popd`, a `cd` on a line with a substitution, and `env -C` or `sudo -D`. So a test root names its own `hold-prs.txt` by absolute path, or works from its own directory. The one sanctioned writer is `bin/hold-row`: `add '<row>'` appends a row relaying Zane's explicit call, and `retire` or `replace` comments out a stale row (Zane, 11 Nov; docs/HOST.md, Holds file). The guard does not block it, since the command names no holds path, and the refusal message points to it.

Commands are split into simple commands and stripped of wrappers (`env`, `sudo`, `timeout`, `xargs`, ...) by `shell.ts`. The quoted command of `ssh`, `vm`, `bash -c`, `sh -c` and `eval` is checked too. A here-document body is data unless a shell reads it.

## Limits

It reads command text. A command built at run time (`eval "$cmd"`, a script file) is not seen, and neither is a write through Python or another interpreter. The pre-push hook and the merge job's unexpected-merge wake stay the backstops. Children spawned by the `subagent` tool load the same package, so the guard binds them too.
