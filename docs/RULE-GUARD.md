# rule-guard extension

`extensions/rule-guard/` turns the onigiri policy's outright bans into code. Before, the policy text was the only thing standing between a session and a ban, and a session either remembered it or broke it. Now a `tool_call` handler blocks the call and returns the reason, so the model sees a refusal it can act on.

## What it blocks

1. **Force-push and skipping the pre-push hook.** `git push` with `-f`, `--force`, `--force-with-lease`, `--force-if-includes` or a `+refspec`, `git push --no-verify`, and `git -c core.hooksPath=... push`. The patent hold lives in the pre-push hook, so a hook skip is a patent-hold bypass.
2. **Merging where a merge job owns merging.** `gh pr merge` (`--auto` included), `gh run rerun` and `gh api .../pulls/N/merge` in any repo listed in `$ONIGIRI_MERGE_OWNED` (comma-separated `owner/name`). A `gh api` call counts only when it writes (a `-X` other than GET, or a field): a GET of `pulls/N/merge` just reads merge status. The repo comes from `-R`/`--repo`, a PR or run URL, the `gh api` path, `GH_REPO=`, or the `origin` remote of the directory the command runs in. A `cd` can fail (`cd x || gh pr merge 1`), so the session's directory and every literal `cd` target earlier in the line all count, and any owned one blocks. Name the repo with `-R` to merge elsewhere from an owned checkout. `-R` takes `[HOST/]OWNER/REPO` or a URL, as gh does. A `{owner}/{repo}` placeholder means that directory's repo. A command whose repo can't be told (a `cd ~/...` or `cd $X`, or a directory with no readable remote) is blocked. Both host launchers set the variable to `trycua/cua` unless it is already set. With it unset, nothing is owned and merges run.
3. **Writing the holds file.** A `write` or `edit` of any `hold-prs.txt`, or bash that redirects into it, runs `tee`, `sed -i`, `perl -i`, `rm`, `chmod`, `truncate` on it, `touch`, `shred` or `dd of=` on it, moves it anywhere with `mv` or `rsync --remove-source-files`, or names it as the last operand of `cp`, `mv`, `install`, `rsync`, `ln` or `ditto` (any operand under `-t DIR`, or a source named `hold-prs.txt` copied to an existing directory, a trailing `/`, or a `$VAR` destination it can't resolve), with options anywhere. Each simple command is parsed into words first, so a commit message that mentions the file, a `< hold-prs.txt` input redirection, a read, a diff and a copy out (`cp hold-prs.txt /tmp/x`, or a `.bak-*` backup) still run.

Commands are split the way `tool-guard` splits them (`find-guard.ts` `commands()`), so `cd x && git push -f` is seen, and shell keywords (`{`, `if ... then`, `do`, `!`) in front of a command are skipped. Wrappers (`env`, `sudo`, `nohup`, `nice`, `timeout`, `xargs`, `VAR=value`) and their options, values included (`sudo -u bob`, `env -u X`), are skipped. git global options and their values (`-C`, `--git-dir`, ...) are skipped too. A `core.hooksPath` override (`-c`, `-c` attached, `--config-env`, or `GIT_CONFIG_KEY_n`) counts only on `push`. The quoted command of `ssh`, `vm`, `bash -c`, `sh -c` and `eval` is checked too, which covers `~/onigiri-vm/vm "git push -f"`.

The matcher is `rules.ts`, a pure module with no pi imports, tested by `tests/rule-guard.test.ts` (`node --test tests/rule-guard.test.ts`).

## Limits

It reads command text, like `tool-guard`. A command built at run time (`eval "$cmd"`, a script file) is not seen, and neither is a write through Python or another interpreter. The pre-push hook and the merge job's unexpected-merge wake stay the backstops. Children spawned by the `subagent` tool load the same package, so the guard binds them too.
